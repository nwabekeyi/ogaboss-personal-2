# Swap Liquidity Reservation & Ledger Fix — Plan

## Key Architecture (user's model)

- **Company owns all funds on Quidax** — users have *no direct Quidax balance*.  
  A user's "BTC balance" or "USDT balance" in our app is purely an internal ledger entry against the company wallet.
- **Company `confirmInstantSwap`** runs on the company's Quidax account — this **does not send crypto

## Model breakdown

```
User swaps USDT → BTC
Company wallet on Quidax:  USDT ↓ ,  BTC ↓
Internal ledger commit (webhook):  fromCurrency pool +reservedDec,  toCurrency pool -toDec
```

- `fromCurrency` (USDT) — **must be reserved**: this is the real money the company is spending. If this is re-assigned to a second user before the swap finishes, the company over-promises.  
- `toCurrency` (BTC) — **must also be reserved**: the company's BTC inventory shrinks. If 10 users each swap 1 BTC and there are only 8 BTC in the `to` pool, 8 succeed and 2 fail with no back-stop.

## Reserves → release on completion (quidax confirmed swap)

```
completed:
  from-pool:  totalBalance += reservedDec        ← company now owns user's USDT
  from-pool:  reservedBalance -= reservedDec     ← unlock what we held
  to-pool:    reservedBalance -= toDec           ← unlock what we held
  to-pool:    totalBalance -= toDec              ← company paid out the BTC
```

So `reserveLiquidity` and `releaseLiquidity` must each lock / unlock **both pools**:
| | `from` pool | `to` pool |
|---|---|---|
| Reserve | `reservedDec` (= `exactFromMinor` + `platformFeeMinor`) | `estimatedToMinor` |
| Release | `reservedDec` | `estimatedToMinor` |
